A cache, not a model

Hindsight

When you fan out N coding agents on one task, Hindsight makes them pay once, in total, for the work all N would otherwise do independently.

A PreToolUse hook intercepts every shell command, keys it on git's own Merkle hash of the live worktree plus a fingerprint of the environment, and asks a shared daemon whether that exact command has already run at that exact state. If it has, the recorded result is replayed instead of executed. Nothing is predicted. A served result is a replay of something that really happened, so the failure mode is a cache miss, never a wrong answer.

01 — The problem

Five agents, five worktrees, one bill paid five times

Launch five agents on one bug in five git worktrees. Each one installs the same dependencies, runs the same failing test to reproduce it, and reads the same files. Nothing tells agent five that agent two already paid for all of it.

The redundancy is structural, not accidental. Agents given the same task start from the same state, so they start with the same moves, and they only diverge as they learn. The opening stretch is both the most redundant and the one where every agent is doing it simultaneously.

02 — How it works

Key the state, measure the purity, coalesce the fan-out

Three mechanisms. The first decides what "the same command at the same state" means, the second decides what may be served at all, and the third is what makes a cold fan-out worth anything.

The key

tree is git's own Merkle hash of the live worktree — git add -A into a side index, then git write-tree — so it covers uncommitted and untracked work. About 36 ms warm on this repo. The persistent side index is what makes that true; a throwaway index costs 220 ms to 1.7 s. It lives in the per-worktree git dir, because worktrees sharing one index would interleave their git add calls and produce a tree describing no real state.

env_fp covers what the tree hash structurally cannot see: installed dependencies, which every ecosystem hides in a gitignored directory. Two worktrees with byte-identical trees and different installed packages must not share a key — that is the single hole that could make Hindsight wrong. It is a directory listing, about 1 ms, deliberately not pip freeze, which would cost 300 ms on every command. If an ecosystem is in use but its state cannot be established, the workspace is marked incomplete and nothing is served at all.

Environment variables are an allowlist, never the whole environment, and their values are scrubbed of the worktree root and home directory before hashing. Harnesses inject per-session variables that differ for every agent by construction; hashing those raw would give every agent a distinct key and reduce sharing to zero.

The purity gate

State is recorded before and after every command, and a record is servable only if both halves are unchanged. Purity is measured, not declared.

That is why this catches what a static table of "read" commands gets wrong: tsc emits .js, cargo test writes target/, and uv sync mutates a virtualenv the tree hash cannot see but the fingerprint can. Installs fall out as unservable automatically, rather than because somebody remembered to list them. Cost is two extra hashes, about 40 ms per command.

servable ⇔ tree_after == tree_before ∧ env_fp_after == env_fp_before

Both halves, measured on every command. A record that fails the gate is still recorded for the corpus — it is simply never served.

Single-flight

A cold fan-out gets nothing from a naive cache: five agents launched at once run the same first command simultaneously, so nobody has finished yet and all five pay — precisely across the opening stretch where overlap is highest. The daemon keeps an in-flight lease per key. The first caller executes; the rest block and are served its result. If the holder dies the lease expires and the waiters execute normally rather than hanging.

Measured on a five-worktree cold fan-out where all five agents run the same expensive command simultaneously: one execution, four served.

03 — What it refuses to cache

The refusals are the product

There is no deny. In Codex, permissionDecision: "deny" blocks the tool call outright, and an agent that cannot run curl is broken. A refusal means the command runs normally — it just never comes back from the cache.

Exactly three policy values
SERVEEligible to be replayed, subject to the purity gate.
RECORD_ONLYRuns normally, recorded for the corpus, never served.
PASSTHROUGHRuns normally, records nothing. The default for anything unrecognized.
Non-hermetic commands

date, curl, $RANDOM, git push, uuidgen, hostname, command substitution, piping into a shell. These are pure by state and still wrong to serve, because state hashing is blind to nondeterminism. This list is correctness, not polish.

Installs

uv sync and pip install mutate a virtualenv the tree hash cannot see — but the environment fingerprint can, so they fall to unservable by measurement. Serving the transcript alone would hand the next agent a recorded "installed" message and no .venv. They stay unservable until an artifact guard can replay the produced directory rather than the text.

Anything that dirties the workspace

Caught by measurement rather than by a list: if tree_after or env_fp_after moved, the record is never servable. tsc, cargo test and go test -c all look like reads and are not.

Code edits

An edit is a decision, not an observation. Letting agent two inherit agent one's patch collapses five independent searches into one and destroys the reason to fan out. Consequences are shared, never the patch: if two agents independently converge on an identical tree, they share every downstream entry for free.

File metadata — the case verification found in production

On the first real fleet run, shadow verification flagged ls -la as divergent. That was not a harness artifact. Long listings print mtimes, sizes and ownership, and git's tree hash deliberately covers none of them, so two worktrees with byte-identical trees legitimately produce different output. The key did not dominate the output.

Nothing else would have caught it. The command mutates nothing, so the purity gate saw identical state before and after and was satisfied. It is not nondeterministic in the date or $RANDOM sense, so nothing about it looked suspicious. Only re-executing it and comparing surfaced the problem. ls -l, stat, du and df are now passthrough; plain ls prints names only and remains servable.

Chains split on &&, ||, ; and |, and the strictest segment wins, so ls && curl example.com is passthrough.

Served results are re-executed behind your back

hindsight verify re-executes commands the cache is willing to serve and diffs the result against what would have been served, evicting anything that disagrees.

In the state it was recorded in

Shadow verification runs agent-side, because the daemon has no worktree and a replay only means anything in the state it was recorded in. Records whose workspace has moved on are skipped rather than judged.

Diffed after normalization

Test runners print durations, temp paths and per-worktree absolute paths that legitimately differ between two correct runs. A raw byte-diff would report divergence on nearly every hit and the counter would be worthless. Both verdicts are reported, so a byte-identical match stays visible.

Divergence is loud

Tested against a deliberately poisoned blob: detected, reported as CACHE_MISMATCH, evicted, nonzero exit. The deny-list will always be incomplete. This is the mechanism that tells you where.

Every number with its denominator

Each time we looked harder at the headline figure it went down, and we published the lower one. Three measurements follow, in decreasing order of how flattering they are.

77% of execution-seconds deleted, on 15 hook-visible commands. The cached arm's counterfactual is 47.3s against a measured baseline of 50.1s, a 5.6% gap between two independent measurements of the same quantity.

  • Wall clock did not improve — 30.5s to 31.8s. Execution dominates wall clock when the suite takes minutes, not seconds.
  • n is 15 commands, one task, one machine. Modern agents use native Read and Edit tools for file work, so only about three Bash commands per agent reach the hook at all. What remains is almost entirely the expensive class, which is favourable, but one run is not a distribution.
  • Round-two sharing depended on convergent fixes. All five agents produced a byte-identical patch. A bug with several valid fixes would leave them at different trees and those hits would disappear.
  • The install pool is still invisible. uv resolved from a warm global cache in under a second here. On a cold cache or with pip, install is the largest single pool.

Removing the model removes run-to-run variance, so the two arms are exactly comparable. Both caveats make the number conservative rather than flattering.

The cached arm's internal counterfactual is 26.7s against a measured baseline of 34.1s. The gap is CPU contention: the baseline runs five expensive commands concurrently and each is slowed by the others, while the cached arm executes one at a time and records an uncontended duration. Pricing avoided work at uncontended speed understates what was avoided.

On a lighter workload where contention is negligible the two reconcile closely: 25.0s counterfactual against a 25.3s measured baseline, a 1.2% gap. That agreement between two independent measurements is the number worth trusting.

Replayed corpus — n = 12,806 commands

Cross-agent reuse under the shipping policy
3.6%

of 12,806 real agent commands. Total avoidable under the same keying is 7.5% of 12,806; the rest is agents repeating themselves, which is not an argument for fanning out. Command-string matching alone gives 16.6% of 12,806 and overstates what can actually be served.

This is a much smaller number than 53.3%, and it belongs here. Keyed the way Hindsight actually keys — on (state, command) rather than on the command string — the honest decay is 16.9% of commands in the opening three steps, falling to 1.0% of commands after step 50.

It is a floor, not an estimate. All 25 tasks in that corpus mix different models (haiku, sonnet, opus) rather than running N instances of one agent, and each starts from a pre-built container, so setup is nearly absent. Both push the figure down relative to the homogeneous fan-out Hindsight targets, which is what the 53.3% measured on a real fan-out reflects. The gap between those two numbers is large and we do not have a principled interpolation between them.

12,806 is the raw command count across multi-agent tasks. Deduplicated it is 11,687. This page uses the raw count throughout.

06 — Install and quickstart

Go standard library, one static binary

Dependencies: the Go standard library, and nothing else. Storage is an append-only JSONL log plus content-addressed blob files. 

$ go build ./cmd/hindsight

$ ./hindsight doctor                    # can this workspace be cached safely?
$ ./hindsight init                      # install the PreToolUse hook
$ ./hindsight doctor --ensure-daemon    # start the shared daemon

$ HP_ENABLE=1 claude
# or: HP_ENABLE=1 codex exec --dangerously-bypass-hook-trust

doctor is the first thing to run and the first thing to run again when something looks wrong. It checks that the tree hash works and how much it costs, that every dependency ecosystem in the repo is covered by the fingerprint, that the cache lives outside the worktree, and that the hook is installed and points at a binary that exists. It exits non-zero if any of that fails, and --json gives the same answer to a script.

The hook is inert unless HP_ENABLE=1

That is deliberate: this repo installs a hook into its own config, so an armed hook would intercept the very session you use to work on the hook.

Other subcommands: hindsight key prints the tree hash and environment fingerprint, hindsight stats prints counters from the daemon, hindsight verify re-executes served results and diffs them, and hindsight replay reports what a recorded trace would have saved.

07 — What we do not claim

The negatives are the credibility

Reproduced from the design doc, in full, because every one of these is a place where a number could have been made to look better and was not.

  • We do not claim "N× faster" without the measured baseline arm.

    The control runs with the hook enabled and serving disabled, so both arms carry identical instrumentation and the only variable is the serve decision. A control measured differently from the treatment is not a control.

  • We do not claim a wall-clock speedup.

    The measured fan-out deleted 77% of execution-seconds across 15 commands and moved wall clock by nothing — 30.5s to 31.8s — because model latency dominated. Those are different quantities and we only claim the first.

  • We do not claim it prevents mistakes.

    It deletes duplicated work. That is all.

  • We do not predict anything.

    There is no model in the system, and that is the cleanest defence available.

  • Published overlap figures match on the command string alone, and they overstate what we can serve.

    Keyed the way Hindsight actually keys, on (state, command), the same corpus gives 7.5% of 12,806 commands avoidable, of which only 3.6% of 12,806 is cross-agent — the rest is agents repeating themselves. Against 16.6% of 12,806 for command-string matching. The honest decay is 16.9% of commands in the opening three steps, falling to 1.0% after step 50.

  • That corpus measures a different population than we target.

    All 25 tasks mix different models rather than N instances of one agent, and each starts from a pre-built container so setup is nearly absent. Both make 3.6% a floor rather than an estimate, which the 53.3% measured on a real homogeneous fan-out bears out. But the gap between those two numbers is large and we do not have a principled interpolation between them.

  • The corpus is a partial run.

    265 records against a manifest describing 736, roughly a third.

  • 11,687 is a deduplicated command count.

    Raw is 12,806. Pick one, say which, never mix them.

  • The per-class seconds in the value table are modelled, not measured.

    Hit counts are real; the seconds come from hardcoded per-class costs. The live counter uses real durations from the fleet run instead.

  • The multi-developer case is untested.

    The corpus is independent attempts at one task.

  • Hindsight shares observations, never decisions.

    Route-sharing between agents is deliberately out of scope. The transition corpus is what would make it approachable later; this is the foundation for that idea, not a retreat from it.

Hindsight is a build cache. We do not describe it as turning your codebase into a world model. The leakage rule it holds — that only a real action with a subsequently observed response may enter the index, never a generated prediction, simulator rollout, teacher datum or judgment — is adopted from Experiential Labs (Apache-2.0, with attribution), because they state it better than we would.
